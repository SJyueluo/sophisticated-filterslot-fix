客户端演示 MOD（无害化）—— backpack-client-demo-1.0.0.jar
整理时间：2026-10-27（北京时间）
适用：Minecraft 1.21.1 / NeoForge 21.1.x（客户端）

============================================================
一、这是什么
============================================================

一个只做"复现并记录"的客户端探针，用来在你自己机器上给
「过滤槽样板被整槽转移成真实物品」留下可验证的运行证据。

它不是外挂程序。下面三条限制是代码里硬编码的：

1. 只在单人游戏或环回地址（127.0.0.1 / localhost / ::1）生效。
   连别人的服务器会直接被拒绝，不发送任何数据包。
2. 不接受用户指定槽位：只作用于当前打开的背包菜单里、已经放了物品的过滤槽。
   所以它无法用来对任意槽位刷东西。
3. 默认不绑定按键，需要你手动去控制里设置；每按一次只发送一次，不循环、不脚本化。

============================================================
二、安装
============================================================

1. 把 backpack-client-demo-1.0.0.jar 放进客户端的 mods/ 目录
   （CurseForge 实例：右键实例 → 打开文件夹 → mods）。
2. 客户端需要 Sophisticated Backpacks + Sophisticated Core，
   版本 3.25.36 / 1.4.18 或更高。
3. 启动游戏。

============================================================
三、使用步骤
============================================================

1. 选项 → 控制 → 按键绑定，找到分类「Backpack Demo (local only)」，
   给「发送整槽转移探针」绑定一个键（默认未绑定）。
2. 进入单人世界，或连接 127.0.0.1 的本地服务器
   （本地服务器需要装同样的两个模组）。
3. 准备一个背包并放一个「拾取升级」（过滤/磁铁/虚空/喂食升级也可以，
   只要它带过滤槽）。
4. 打开背包，切到该升级的设置页，把一个物品（比如钻石）点进过滤槽。
   这是正常操作，不消耗物品。
5. 按你绑定的键。

聊天栏会输出类似：

    [backpack-demo] sent transfer_full_slot for filter slot 164 (minecraft:diamond x1)
    [backpack-demo] minecraft:diamond: storage 0 -> 1, inventory 1 -> 1 | net 1 => DUPLICATED (+1)
    [backpack-demo] written to ...\.minecraft\backpack-demo\evidence-....json

同时会写一份 JSON 证据，字段包括时间、地址、槽位号、物品、前后数量、净增。

============================================================
四、当前版本的已知限制
============================================================

- 本机没有图形环境，也没装客户端专用的映射库，所以**没能实际跑起来验证**。
  已完成的是：编译通过 + jar 结构正确 + 网络层字节验证（见第五节）。
  实际点击效果需要你在客户端里跑一次确认。
- 单人世界里服务端与客户端同进程，"网络"是本地环回。它证明的是
  「客户端能把这个包发出去、服务端处理器接受并搬移物品」，
  不等于公网服带宽下的行为，但走的是同一套编码与分发代码。
- 它不修改任何模组文件，卸载即失效。

============================================================
五、已产出的运行外证据（可直接引用）
============================================================

用模组自己的 StreamCodec 对同一个 payload 做编码/解码，得到客户端
实际会发出的字节：

    payloadType      = sophisticatedcore:transfer_full_slot
    slotIdSent       = 164
    wireBytes        = 4  [00 00 00 A4]
    slotIdDecoded    = 164
    roundTripMatches = true

也就是：客户端只需要发 4 个字节（一个 int），服务端解码后直接拿去
getSlot(slotId) 并调用 quickMoveStack，没有任何来源校验。

服务端侧的运行证据（重启后物品仍在）在 evidence/ 目录的
A / C / E / F / G 各 JSON 里。
