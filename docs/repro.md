精妙背包 过滤槽复制 —— 本机联机服复现包
整理时间：2026-10-27（北京时间）
目标：在本机跑一个"真正的专用服务器"，用真实网络连接复现，物品只用泥土。

============================================================
零、先明确一件事
============================================================

客户端演示 MOD 的地址限制是：只允许单人游戏或环回地址
（127.0.0.1 / localhost / ::1）。

这不是"只能单人"，而是"只连自己机器上的服务器"。
本机专用服务器是一个独立进程、走真实 TCP socket、走真实的
NeoForge 报文编解码与分发 —— 和公网服唯一的差别是地址。

连别人服务器会被拒绝，这是刻意的。

============================================================
一、服务器侧准备
============================================================

1. 服务器 mods/ 只需要两个模组（都不需要 JEI 即可复现复制）：
     sophisticatedbackpacks-1.21.1-3.26.15.2227.jar
     sophisticatedcore-1.21.1-1.5.18.2431.jar
   （旧版 3.25.36 / 1.4.18 同样可复现，见 evidence 里的 E/F 档）

2. 可选：把 backpack-check-1.0.0.jar 也放进去，启动一次会自动
   给出两档判定并写 JSON，然后自己关服（需要 -Dbackpack.check.exit=true）。

3. server.properties 关键项：
     online-mode=false
     server-port=25871
     server-ip=127.0.0.1
     level-name=backpack-repro
     gamemode=creative
     spawn-protection=0

4. 启动后进服，给物品（创造模式，用命令）：

     /give @s sophisticatedbackpacks:netherite_backpack
     /give @s sophisticatedbackpacks:pickup_upgrade
     /give @s minecraft:dirt 64

   用净界合金背包是因为它有 7 个升级槽和 120 格储物，
   过滤槽编号稳定（第一个过滤槽 = 164）。

============================================================
二、客户端侧准备
============================================================

1. 客户端 mods/ 需要：
     backpack-client-demo-1.0.0.jar   （本包提供）
     sophisticatedbackpacks / sophisticatedcore （与服务器同版本）

2. 启动游戏，进入
     多人游戏 → 直接连接 → 127.0.0.1:25871

3. 绑定按键：
     选项 → 控制 → 按键绑定 → 分类「Backpack Demo (local only)」
     随便给「发送整槽转移探针」绑一个不冲突的键。

============================================================
三、复现步骤（照做，约 1 分钟）
============================================================

1. 手里拿净界合金背包，右键打开。
2. 把拾取升级拖进背包的任意一个升级槽（背包右上区域）。
3. 点击该升级的标签页，进入升级设置界面。
4. 手里拿泥土，点一下过滤槽 —— 泥土进入过滤槽，且手里的泥土数量不变
   （这一步本身就是"样板不消耗物品"的正常行为）。
5. 记下当前数字：
     - 玩家背包里的泥土数量
     - 背包储物区里的泥土数量（此时应该是 0）
6. 按你绑定的键。

聊天栏会输出：

    [backpack-demo] sent transfer_full_slot for filter slot 164 (minecraft:dirt x1)
    [backpack-demo] minecraft:dirt: storage 0 -> 1, inventory 64 -> 64 | net 1 => DUPLICATED (+1)
    [backpack-demo] written to ...\.minecraft\backpack-demo\evidence-....json

含义：过滤槽被清空，背包储物区多出 1 个泥土，
而你手里的 64 个泥土一个没少。净增 1。

再重复第 4-6 步 5 次 → 储物区累计 +5。

============================================================
四、对照（证明不是"正常转移"）
============================================================

同一套环境下，不碰过滤槽、直接对储物格里的一格泥土按 Shift 点：
泥土被"搬"到玩家背包，总数不变（没有净增）。

只有经过过滤槽 + transfer_full_slot 这条路，才会净增。

============================================================
五、服务端侧证据（不需要客户端也能跑）
============================================================

backpack-check-1.0.0.jar 在服务器上跑一次即可，默认用钻石，
用泥土跑：

    java ... -Dbackpack.check.item=minecraft:dirt -Dbackpack.check.exit=true ...

实测（3.26.15 / 1.5.18，NeoForge 21.1.265）：

    无修复：probeItem=minecraft:dirt  tier1=+1  重复5次=+5  普通点击=0  回归=3  → VULNERABLE
    加修复：probeItem=minecraft:dirt  tier1=0   重复5次=0   普通点击=0  回归=3  → FIXED

原始 JSON 见 evidence/I-泥土复制-无修复.json 与 J-泥土复制-加修复.json。

============================================================
六、说明
============================================================

- 本包不含"可对任意服务器使用"的客户端程序；地址限制写在代码里。
- 演示唯一目的是给模组作者提供可复现、可核对的证据。
- 用泥土是因为它没价值，能清楚说明"这是逻辑缺陷"而不是"偷贵重物品"。
